# 履歷以外

## LinkedIn

履歷是主動投遞，LinkedIn 是被動被找到；兩者都要顧，內容大多可以共用。Recruiter 用關鍵字加 Boolean search（AND、OR、NOT）找人，先看到的是搜尋結果卡片：headline、目前職位、地點、學校。

- **Headline**：寫你希望被搜尋到的定位，可用 `|` 加關鍵技能（例：`Backend Engineer | Python, Go | Distributed Systems`）。不要寫 "Looking for opportunities"。
- **求職中**：開啟 Open to Work（可設定只讓 recruiter 看到），不要佔用 headline。
- **目前職位**：可以寫成更能反映實際工作的描述；沒有工作時也建立一個 current 條目（例如接案或專案），避免搜尋排名下降。
- **About**：比履歷 summary 長也沒關係（1–2 段），寫你能帶來什麼與求職動機；hiring manager 會讀。
- **經歷描述**：可以比履歷詳細；放入 recruiter 會搜尋的關鍵字。
- 刪掉與職涯故事無關的經歷。
- 照片不是必要；要放就放清楚、友善的專業照。
- 多連結同事與曾聯絡過你的 recruiter（關係越近，排名越前）。
- 已確定要搬去的城市可以更新所在地；需要簽證時謹慎使用。

## GitHub

只有值得看的時候才放連結。Hiring manager 點進來會看：置頂專案在做什麼、README（怎麼跑、怎麼測）、程式碼品質與命名、有沒有測試、在大型專案中的 PR 與互動。
他們不看：contribution 格子、followers、repo 數量。

- 建立 profile README（建立與帳號同名的 repo）：簡介、你想被注意到的專案
- 置頂最好的專案（最多 6 個），每個都填 description
- 置頂專案的 README：是什麼、截圖或範例、如何執行、如何測試、技術亮點
- 履歷是英文、審閱者讀英文時，README 至少要有英文摘要

## 技術文章

- 不要只放部落格首頁：在履歷上點名 1–2 篇最相關的文章，標題本身就是專長證據
- Stack Overflow 只在活躍且能佐證專長時放；其他社群媒體不放

## Cover letter

- 大公司幾乎不看；小公司、新創，或能直接寄給 hiring manager 時才值得寫
- 一份已客製化的履歷，本身就有 cover letter 的功能
- 寫的話：短；先講公司（證明你研究過、認同其方向）再講你；說明為什麼適合並舉例；提到公司名；用 PDF
- 個人化優於模板——模板內容幾乎只是重複履歷
- 語氣依地區與公司文化調整：美國新創可以直接活潑；英國、澳洲或傳統公司偏正式；資深職位避免過度熱情

## 回饋與打磨

- 用完全不同的結構寫第二份履歷，再合併兩份的優點成第三份——逼自己找出新的成就寫法
- 文法工具（Grammarly 類）+ 可讀性工具（Hemingway 類）+ 自己朗讀
- 找朋友做 5 秒測試：看完說出第一印象與記住了什麼
- 在線上社群求回饋前先去識別化（姓名、電話、公司內部資訊）；回饋打折聽
- 模板：選單欄、由上而下、為審閱者設計的（例如 Pragmatic Engineer 模板、Standard Resume 的 Parker），不要選設計師導向的花俏模板
