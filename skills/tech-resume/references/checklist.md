# 履歷健檢清單

逐項檢查；每個不通過的項目都要能指出原文位置。

## 1. 第一印象（6 秒掃描）

- [ ] 年資算得出來：畢業（或預計畢業）月份年份清楚，工作日期清楚
- [ ] 與職位相關的技術在第一頁、容易掃到（技能區與 bullet 內都有）
- [ ] 職稱與公司醒目（粗體或固定位置）
- [ ] 有所在地；跨國申請時明寫工作許可或簽證狀態，否則容易被歸到「需要簽證」那一疊
- [ ] 最亮的訊號在第一頁看得到：知名公司、獎項、專利、論文、開源核心貢獻、名校

## 2. 基本規則

- [ ] 沒有錯字、沒有文法錯誤（拼字檢查 + 文法工具 + 自己朗讀 + 請別人看）
- [ ] 標點一致
- [ ] 聯絡資訊精簡：email、電話、城市與國家；不寫完整地址
- [ ] 倒序排列，最新的在最上面
- [ ] 沒有照片、生日、性別、國籍、婚姻、子女、宗教等容易引發偏見的資訊（在地慣例另議）
- [ ] 長度：學生、新鮮人 1 頁；多數人不超過 2 頁；資歷 8–10 年以上或管理職最多 3 頁
- [ ] PDF；檔名像 `Firstname_Lastname_Resume.pdf`，不帶版本號或公司名

## 3. 結構

- [ ] 段落順序依「最能證明你適合」排列（見 structure-by-level.md）
- [ ] 有工作經驗時，工作經驗靠上
- [ ] 近期經歷寫得比早期詳細；10–15 年前的經歷可精簡或刪除
- [ ] 刪掉和職涯故事無關的工作
- [ ] 同公司的升遷分開列，一眼看得出來
- [ ] 非標準職稱可在括號補實際職能（如 `Software Engineer (Associate)`）；僅限實際職責與頭銜長期不符時，不可灌水
- [ ] 很快被升遷吸收的短期職位可以省略
- [ ] Summary：資淺者預設不放；要放就必須針對 JD、具體、短

## 4. Bullet（細節見 bullets.md）

- [ ] 寫成果與影響，不是職責清單；多數 bullet 有數字
- [ ] 主動動詞開頭；過去職位用過去式，現職可用現在式，整份一致
- [ ] 主角是你：不用 we 或 team 當主詞（英文履歷省略 I 即可）
- [ ] 沒有弱化語：helped, assisted, participated, sometimes, occasionally, was responsible for, worked on
- [ ] 沒有外人看不懂的內部代號、專案名或縮寫
- [ ] 沒有陳腔濫調：team player, fast learner, passionate, detail-oriented（改用事實證明）
- [ ] 關鍵技術出現在 bullet 中，且與技能區重疊
- [ ] 每條不超過 2 行；每職位 3–5 條；不用子 bullet；不用整段文字
- [ ] 不以 "etc." 結尾，沒有口語或俚語

## 5. 技能區

- [ ] 只列每天上工都用得上、面試被追問也撐得住的
- [ ] 依熟練度與相關度排序，最強的放前面
- [ ] 沒有自評（Expert、Proficient、星等、百分比）——評高被懷疑、評低被扣分
- [ ] 刪掉人人會或太瑣碎的工具（Word、Trello、Jira、IDE、Slack）
- [ ] 分類清楚（Languages / Frameworks / Cloud & Infra / Data & ML / Other），類別名稱不重複
- [ ] 不熟但相關的技術，必要時另列 `Familiar:`
- [ ] 多年沒用、已生疏的語言刪掉（也降低年齡偏見）
- [ ] bullet 用到的關鍵技術在技能區找得到，反之亦然

## 6. 格式與版型

- [ ] 單欄、由上而下（雙欄對工程職位幾乎只有壞處；設計、UX 職位例外）
- [ ] 字體、字級、對齊、間距一致；用 tab 或表格對齊，不用空白鍵湊
- [ ] 粗體只給職稱、公司、日期、段落標題；句子中間不亂加粗
- [ ] 顏色節制且用法一致；不用花俏模板（內容佔 95%，樣式 5%）
- [ ] 日期格式一致且無歧義（`Jun 2021 – Jul 2022`，不要 `06/11–07/12`）；幾年前的經歷可只寫年份
- [ ] 日期靠右對齊，方便直向掃描
- [ ] 沒有為塞進一頁而縮小字級、擠掉留白
- [ ] 第二頁不重複頁首

## 7. 連結

- [ ] 全部可點擊；實際打開過，不是 404 或空頁
- [ ] 連結文字短（`GitHub`、專案名），不貼長 URL
- [ ] 連結顏色不搶職稱與日期的注意力（與正文同色加底線即可）
- [ ] 聯絡方式與個人連結合計不超過 4 個；只放有內容支撐的（空的 GitHub、多年沒更新的網站不如不放）
- [ ] 連到具體作品（某個 repo、某篇文章）優於只連首頁
- [ ] 不放 Instagram、X/Twitter、Quora、Skype、接案平台等（除非與職位直接相關）；Stack Overflow 只在活躍且能佐證專長時放
- [ ] LinkedIn 內容與履歷一致

## 8. 通常可刪的內容

- [ ] 照片
- [ ] 推薦人清單、"References available upon request"
- [ ] 別人對你的讚美、績效評語引言
- [ ] 口說語言區（英語為工作語言的公司預設你會英文；JD 要求或目標公司在意時才放）
- [ ] Objective 或求職目標（「尋找軟體工程職位」）
- [ ] 隨考隨過的低門檻線上證照（高相關證照保留；顧問、政府、非科技公司更看重證照）
- [ ] 不高的 GPA（高才寫）
- [ ] 過度描述公司本身（篇幅要給你的成果）

## 9. 故事與定位

- [ ] 職稱與經歷看得出成長：責任變大、主動性增加、問題變難
- [ ] 一份履歷只講一個方向；跨多種職類就分版本；IC 與 Manager 各一份
- [ ] JD 最重要的 3–5 項要求，在履歷上半部都找得到證據
