# 閱讀筆記格式 v3.2.1

YouTube 解說、Podcast 與課程錄音都預設使用這份文章格式。[course-format.md](course-format.md) 只用來維護既有的舊版時間軸筆記，新筆記不要再用它；舊筆記要等使用者指定才遷移，不批次改。`check` 檢查結構，不證明內容正確或來源完整。

## 來源與身分

Frontmatter 保留 `title`、`date`、`source_type`、`source`、`transcript_method`、`tags`；可取得才填 `channel`、`published`、`duration_seconds`，不猜日期或名字。類型標籤依來源使用 `type/video-note`、`type/podcast-note`、`type/course-note`。

新版加：

```yaml
note_style: reading-v3
generator: media-note
skill_version: 3.2.1
```

遷移既存筆記時保留原來源、身分欄位、建立日期、標籤與路徑；另加 `revised` 寫實際修改日期。不要把講者當年的職位或預測改成今天的現況。無可用時間戳時用 `timeline_mode: degraded`，在開頭說明影響，不編造精確秒數。

## 讀者看到的文章

### 開頭的順序

H1 標題之後依序放：

1. **導讀表格**：一句引言帶出表格，欄位是「段落｜時間｜內容」，每列是一個大段落（2–5 列），內容欄寫關鍵詞，不寫長句。
2. **主軸段落**：一段一般文字，交代全篇反覆出現的主軸、結論成立的條件，以及講者說法與來源不一致的地方有哪些。主軸用粗體寫成一句。
3. `> [!info]- 來源` 與 `> [!warning]- 轉錄品質與無法還原的段落`，**兩個預設都摺疊**。讀者平常不看來源與轉錄品質，內容讀起來怪怪的才會回頭查，所以不佔版面。
4. **總覽圖**：能解釋全篇關係與閱讀路線的圖；多主題節目用並列問題地圖，不硬造唯一論點。圖下一行斜體圖說，再接 `> [!note]- 圖的文字等值內容`，用文字寫出圖中同等資訊。

表格回答「講了什麼、在哪個時段」，圖回答「彼此怎麼連起來」，兩者都要。不要把所有條列塞入圖，也不要靠華麗裝飾取代理解。可用可編輯 SVG、PNG、Mermaid 或其他合適形式；圖例區分因果、條件、對照與閱讀順序，沒有來源支持的因果不能畫成箭頭。保留 alt text，檢查手機與桌面的實際可讀程度；未能實測就據實記錄。

```markdown
這堂課分成三段：

| 段落 | 時間 | 內容 |
| --- | --- | --- |
| 迴歸收尾與實作 | 00:00–46:46 | R²、簡單／多元迴歸、資料檢查、訓練測試切分與過擬合、Bonus |
| 分群演算法 | 46:46–1:22:44 | K-means、K-medoids、階層式、DBSCAN |
| 評估與延伸 | 1:22:44–1:45:28 | Silhouette、ARI、NMI、研究分享、論文、Iris |

整堂課的主軸是 **拿到資料先看資料，再選模型。** 迴歸要先看……
```

### 正文

正文用回答問題的 H2；一節有兩個以上可獨立查閱的子主題時（例如 DBSCAN 的「參數與三種點／步驟與優缺點」）才加 H3，短節不加。分段依語意、問題或推論鏈，不依每一兩分鐘切段。鋪陳、例子、反駁和轉場可以接在同一論證內，不強迫每段都有「核心主張／必要細節」。保留講者主要展開順序；局部合併重複或回接開場例子時給自然承接，不能把後來的結論放到前面造成講者早已證明的錯覺。

段落要解釋誰做了什麼、透過哪個步驟造成什麼結果，以及何時不成立。必要因果橋接不能藏在摺疊區。第一次遇到專業詞先用白話說它在此做什麼，再給名稱或英文；解釋不能依賴另一個未解釋的詞。避免「把這幾層拆開」「看懂這條鏈」等空泛口號取代具體關係。

例子與數字若讓理解更清楚，可以加入並明寫「閱讀輔助／假設例子」。交代簡化條件、數字單位和口徑，不能裝成原節目數字或真實觀測。原節目的故事、反例、替代解釋與限制，若負責支撐或改變主張就保留；不要拿整理者新例子取代原例證。補充篇幅由理解需要決定，不用每分鐘行數、字數或 token 量代表完整。

必要解釋留在正文，細部查證、校正紀錄和額外閱讀收在預設摺疊的 callout。主動回憶題是選配；有自測題便附可摺疊答案，不強加五章模板或題數。

## 版面與標記

**列點或段落。** 三項以上平行的東西（步驟、清單、選項、缺點、參數）才列點，有先後順序的用編號；有「因為…所以…」的推理維持一般段落，不要把推理拆成碎句。真正的多欄比較用表格。

**分號就是列點的訊號。** 不用 `；` 把兩個以上並列的子句串成一長句。依內容改寫：

- 並列的幾件事或幾個面向：寫成一句導言（以冒號結尾），後面一項一個列點；有順序用編號。
- 一句話加一句補充或理由：改成兩個句子，用句號分開。
- 主軸、結論這類帶出幾個面向的開頭段落，也照這個寫：先一句導言，再每個面向一個列點，列點開頭用粗體標面向名稱（`**迴歸**：…`），列完回到一般段落。

例外：括號裡的術語說明（`（term；gloss）`，這是固定的術語格式）、程式碼、表格儲存格、圖說與 alt 文字。圖說與 alt 不拆成列點，改用句號分成幾個短句，不使用分號。巢狀列點一律用 Tab 縮排，一層一個 Tab，不用空格（`check` 會擋）。表格內 wiki 別名的 `|` 要寫成 `\|`。

**粗體。** 用在兩處：術語第一次出現，以及列點開頭的小標（`**前半｜迴歸**：…`）。同一術語之後不再加粗，不用粗體強調整句。

**術語第一次出現**一律寫齊三樣：中文名、英文全名（有縮寫就接在後面）、一句白話，格式固定，不能有的術語有英文、有的沒有：

- 有通行中文名：`**決定係數**（coefficient of determination，R²；比較模型與「永遠猜平均值」誰的誤差小）`
- 英文名就是常用名：`**K-means**（K 平均法；把資料分成 K 群、每群用一個中心點代表）`
- 工具或套件：`**scikit-learn**（Python 的機器學習套件）`

白話不能依賴另一個沒解釋過的詞；縮寫之後才可以單獨使用。

**螢光 `==…==`。** 每個 H2 最多一處，標正文中最該記住的那一句結論；不標術語、不標整段。

**顏色只靠 callout 類型**，不用 HTML 標籤或自訂色碼（深色模式與匯出都會壞）。固定對照：

| 用途 | 寫法 | 顏色 | 預設 |
| --- | --- | --- | --- |
| 來源與素材說明 | `> [!info]- 來源` | 藍 | 摺疊 |
| 這節記住 | `> [!tip] 這節記住` | 綠 | 展開 |
| 課堂練習、作業細節 | `> [!example]- …` | 紫 | 摺疊 |
| 講者說法與講義不一致、轉錄問題、本筆記驗算出的錯誤 | `> [!warning]- …` | 橘 | 摺疊 |
| 外部查證（`check` 會數來源連結） | `> [!research]- …` | 預設 | 摺疊 |
| 整理者補充、推論、圖的文字等值內容 | `> [!note]- …` | 藍 | 摺疊 |
| 自我檢查 | `> [!question]- …` | 黃 | 摺疊 |

**這節記住。** 每個有教學內容的 H2 結尾放一個 `> [!tip] 這節記住`，用 1–2 句收斂本節結論與成立條件，可呼應螢光句但不逐字重複。它是整節最後一個區塊（圖與 callout 之後）。純公告、作答時間、無內容的節不加。

**公式。** 用 LaTeX：完整公式獨立成 `$$…$$` 區塊，句中的符號用 `$…$`；公式後接一句白話，說明每個符號是什麼。

**程式碼。** 講義、課程 notebook 或講者有示範程式時，操作步驟直接寫成 ```` ```python ```` 程式碼區塊，不要改寫成「1. 匯入… 2. 定義…」的文字清單。每行或每段加中文註解，說明在做什麼、關鍵輸出是多少（例如 `# 訓練 R²：0.733`）。程式以講義截圖或課程 notebook 的原文為準；整理者補上的行（例如投影片沒寫的 import）要在註解標明，不確定的值保留講義原本的空格或標成要自己填。概念演算法（例如 K-means 的四個步驟）不是程式碼，維持編號清單。

**講義引用要能點。** 不寫「D1 p.12」這種讀者還得自己去翻的代號。正文、回聽行與圖說提到講義頁時，用 Obsidian 的 PDF 頁面連結，點了直接跳到那一頁：`[[<vault 內 PDF 路徑>#page=N|<講義簡名> p.N]]`，例如 `[[Week3/課程 PPT/1. Regression.pdf#page=25|迴歸講義 p.25]]`。頁碼是 PDF 第幾頁；範圍連到第一頁、顯示寫範圍；表格內的 `|` 寫成 `\|`。講義簡名用讀者看得懂的名字（迴歸講義、Bonus 講義），在 `> [!info] 來源` 一次列出每份講義的簡名與檔案連結。

**截圖只放正文給不了的資訊。** 投影片帶有正文沒有的東西才截圖：圖表與散布圖、示意圖與流程圖、正文只摘了幾個數字的完整表格、執行結果圖、講者指著畫面講解而文字說不清的內容。投影片只有文字、公式、程式碼，或它的數字已經完整寫在正文時，不截圖，改用上面的頁面連結。截圖接在它支撐的段落旁，圖說要寫出圖裡多了什麼資訊。

一節的骨架：

```markdown
## DBSCAN：K-means 找不到的形狀怎麼辦？

*回聽 1:16:11–1:22:44｜[[Week3/課程 PPT/2. Clustering.pdf#page=37|分群講義 p.37–49]]*

引言段落，**DBSCAN**（Density-Based Spatial Clustering of Applications with Noise，帶雜訊的密度分群；用密度分群、會標出離群點）……

### 兩個參數與三種點

- **邊界點**：……
- **離群點**：……

==一個群至少有一個核心點，加上所有可到達的邊界點。==

```

## 可查而不切碎的時間戳

每個主要語意章節的標題下方第一行放回聽範圍，後面用「｜」接對應講義頁的 PDF 頁面連結（有的話）。YouTube 加對應時間連結；Podcast／本機音訊寫範圍即可。例如：

```markdown
*回聽 00:00–02:35｜[[Week3/課程 PPT/1. Regression.pdf#page=12|迴歸講義 p.12]]*
*[回聽 01:30–06:18](https://www.youtube.com/watch?v=ID&t=90s)｜00:00–01:30 是事件開場與問題預告*
```

全篇來源區間的交代放在工作區 coverage，正文可合併同一問題的區間並註明回接位置。廣告、閒聊可一行交代；實際素材缺口明標時間與影響，不假裝連續或默認是無聲片尾。回聽範圍不能倒置、超出素材或與連結秒數不符。無字幕／ASR沒有辨識出文字，不證明沒有聲音；區分字幕讀取、原畫面查看與實際聽辨。

## 原圖與查證

原片有資訊的圖表、流程、文件或投影片應接在其解釋旁，總覽圖不能取代它們；投影片要不要截圖，依「版面與標記」的截圖原則判斷。使用 driver 匯出來源圖；已存在的原圖保持位元組與來源身分。新增總覽圖標成整理者製作。圖附 alt 或 wiki 顯示說明，再給圖說、時間或 PDF 頁；說明讀法、與本段關係、圖能證明到哪裡。保留裁切／文字看不清的限制，不依看不清的圖猜數字。

研究依 [research-policy.md](research-policy.md)。用「講者認為／節目提到」區分原觀點，用「閱讀輔助／這裡補充」區分整理者解釋，用查證 callout 放外部確認、修正或未知。不要默默替換講者說法。所有正式外部證據要打開原文，保存對應主張、支持範圍與查閱日期；連結數量不代表獨立性。

## 工作區的來源覆蓋與驗收

技術證據留本次工作區，不堆在 vault 閱讀頁。保存完整來源讀取、source ID、來源與筆記雜湊、coverage、圖像與連結核對、check 結果及發布後讀回。

Coverage JSON：`source` 與 frontmatter 完全相同，`source_file` 為工作區完整來源檔的路徑，`source_sha256` 為實際讀取的完整逐字稿／字幕檔 SHA-256，`note_sha256` 為待發布筆記 SHA-256，`units` 依說話順序列全篇語意單位。每項有 `id`、`start`、`end`、`role`、`required`、`action`（保留／合併／略去／未知）、`article_location`、`rationale`。無時間的來源以 `source_locator` 代替 start/end。略去也要記理由，未知不能標全覆蓋。

逐一反查：新文主張在哪個來源；來源的因果步驟、限定、數字口徑、反例、替代解釋、故事功能是否仍在；刪的是重複還是證據；圖有沒有把對照畫成因果；補充是否冒充原話。核心推理或必要資料不足就保留限制、補合法來源，或暫緩該篇，不只從 AI 舊筆記二次改寫。研究不需要為每個不重要數字無限擴張。

```bash
uv run ~/.agents/skills/media-note/scripts/medianote.py check NOTE.md --coverage WORK/coverage.json
```

`ok` 只表示結構通過。`coverage_status` 只表示 sidecar 結構與來源／筆記身分可核對；它也不證明語意支持。完成上述人工 source review 才能驗收，不能拿 warnings 清空或零錯誤當內容品質證明。重寫時保存人改；檔案 hash 改變便停止發布並重新比對，不覆蓋同時寫入的內容。
