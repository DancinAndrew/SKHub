# 網頁文章收錄與歸檔

將指定文章變成可閱讀、可追溯的 Markdown 原文。保留作者的長篇推理、例子、數字、引文、圖表、來源連結及語氣；不自動摘要、翻譯、改寫論點或新增學習心得。

使用者已表明「之後直接丟網頁連結就收錄」時，該收錄脈絡中的裸文章連結即可開始，不再問要做什麼。若連結伴隨明確的解釋、比較或其他要求，以當次要求為準，不額外歸檔。

## 先確定來源與歸檔位置

- 輸入可為一個或多個文章 URL、已下載的 `.md`，或兩者。使用者提供本機全文時，優先以該檔為原始輸入，避免用網路預覽覆蓋較完整版本。
- 先讀目的 vault 的 `AGENTS.md`、首頁及必要的維護規則，查看現有來源資料夾與一至兩篇同作者範例。沿用目前結構，不恢復歷史分類。
- 可以從 Obsidian 已登錄 vault、當前工作區與使用者指定路徑確認候選位置；不要為了分類廣泛掃描私人全文。
- 同作者、同系列已有明確來源資料夾，就直接歸檔。Business & Finance 的 KP 文章使用 [KP 與清冊流程](references/business-finance.md)，先確認路徑仍存在。
- **位置不明時先問使用者。** 提供具體候選 vault／資料夾，必要時提議新資料夾。不要擅自建立新的分類體系、把所有文章塞進目前 vault，或新設 `inbox`。
- 可以先下載、備份與整理候選檔，等待位置回覆；未收到回覆前不執行有歧義的歸檔。使用者已明確指定或確認過本次目的地，就不用再問。

## 取得可用的全文

1. 在已授權的工作區建立本次暫存目錄，保存原始 Markdown；從 HTML 擷取時，也保存可取得的頁面 HTML 或等效原始匯出。記錄 requested URL、實際 URL、取得時間、擷取方式與原始檔 SHA-256。
2. 使用可用工具取得**實際文章內容**：
   - `.md` 直連：直接下載原檔，檢查內容確實是 Markdown，而非登入頁或錯誤 HTML。
   - 一般 HTML：優先遵循可用的 `ego-browser` skill，擷取文章 DOM、標題、作者、明示日期、canonical URL 和圖表；使用已安裝的 HTML→Markdown 工具轉換。不要用瀏覽器的操作快照或搜尋摘要充當全文。
   - 無需登入的靜態文章，也可依 `defuddle` skill 使用 `defuddle parse <URL> --md -o <raw.md>`。先確認現有工具可用；未經授權不要為一次收錄直接全域安裝依賴。工具缺少時優先使用可用的瀏覽器／既有轉換器。
   - 登入、動態載入或付費文章：使用使用者已有授權的瀏覽器狀態取得可見全文。遇到登入或權限阻礙，請使用者完成登入或提供匯出；不繞過存取限制，不把預覽標為全文。
3. 對照頁面與擷取檔的開頭、末尾、章節、表格及重要圖表。處理懶載入圖片，將相對連結解析為完整 URL；記錄擷取遺漏，不自行補寫缺失段落。
4. 文章網址不能從內文引用的其他文章推定；發表日不能從檔案時間、文內事件年份或取得日期推定。缺少就留未知。保存作者原有的錯字或可疑說法，另記明顯的擷取問題。

若只能取得摘要／預覽／截斷內容，先保留暫存並說明缺口。只有使用者同意收錄節錄時，才以明確 `excerpt` 狀態歸檔。

## 整理格式，不重寫內容

先保留原始輸入，再編輯候選檔。本文只依網站或 vault 既有做法放標題及來源資料；有獨立來源清冊時，不強行在作者正文塞入通用 frontmatter。

- 修正空行、縮排、清單標記、章節層級與可辨識的重複網頁標題。章節先後不變；同名標題不代表可刪，只有確認為重複網頁介面或錯置的重複標題時才移除，保留變更紀錄。
- 長文在主要章節前加入 `---`，前後留空行；不要在檔案第一行加分隔線，也不要每個小節都加。
- 對 Substack 的 `[ ![圖片](縮圖網址) ](同圖大圖網址)`，可移除外層同圖連結，保留原圖片、說明與圖片順序。圖片連到外部證據頁時保留該連結。
- 圖表、文章封面及具有資訊的圖片全部保留。延伸閱讀卡片的裝飾縮圖可移除，但必須留下標題、明示日期、原有摘要及原文連結。不要把付費文章的卡片摘要當成全文。
- 延伸閱讀卡片可轉為 `> [!quote] 延伸閱讀`。只有網址／標題能唯一確認對應本機文章時才加 wikilink；模糊對應保留外部網址，不憑主題相似造連結。
- 文末社群、推薦碼與訂閱推廣保留在 `> [!info]- 作者推廣資訊` 收合提示框。正文中的商業分析、前言或與論證相連的段落不因含品牌名稱就刪除或收合。
- 表格保留完整內容、欄位與單位。表格中的 wikilink 別名分隔符寫成 `\|`，逐列檢查欄數。程式碼、數學公式、引文、註腳不得用全域正規表示式粗暴整理。
- 圖片可沿用遠端 URL。若使用者要求離線保存，才下載附件到 vault 既定位置並驗證檔案、改寫相對連結；未下載不要聲稱可離線閱讀。

## 去重、寫入與歸檔

- 以可確認的原文 URL、標題／期數及原始內容雜湊比對既有來源。同標題不同內容需判斷是否新版；同內容不同檔名不重複收錄。
- 不覆寫已凍結的來源。新版另存並連到舊版；一般既有筆記的可編輯規則不等於來源可改寫。
- 格式確認後才寫入正式位置。若有來源清冊及產生目錄，依該 vault 現有工具更新，不另建競爭清冊。
- 多檔搬移或清冊更新時依目的 vault 的規範保存計畫、備份、前後雜湊及收據。寫入前再次核對原始檔未被同時修改；拒絕覆蓋同名檔。
- 正式檔與清冊讀回通過後，才移走使用者交付的入口檔；保留可還原的原始備份。不刪除使用者提供的 vault 外原檔，除非使用者要求搬移該原檔。
- 收錄不代表已讀、已理解、已查證；不因此新增閱讀進度、持倉、投資立場或主題摘要筆記。

## 驗收與交付

- 比較原始／候選內容：正文段落與次序、數字、引文、圖片及圖說、外部證據連結都保留。記錄允許的格式變動，避免僅靠字數相近判定無損。
- 檢查標題層級、清單、表格欄數、提示框、圖片語法及本機連結；再讀回實際歸檔檔案核對雜湊。
- 執行目的 vault 的結構檢查，區分新增問題與既有警告。若 Obsidian 可用，查看閱讀模式；不可用時明確記 `NOT RUN`，不聲稱已做視覺驗證。
- 回覆正式檔案連結與精簡處理結果。有缺頁、未知來源資料、遠端圖片或未完成檢查等實際限制時才提及。未完成歸檔時清楚報告停在哪一步。
