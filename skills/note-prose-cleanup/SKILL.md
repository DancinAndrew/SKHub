# 筆記文字清理

讓讀者能順著概念、理由與例子讀下去。先辨認哪些句子在教學，哪些句子只是反覆交代整理者做過什麼，再決定如何改寫。依句子的作用判斷，不依關鍵字批次刪除。

## 適用範圍

- 修訂使用者指定的既有筆記、解說或文章；預設直接改回原檔。
- 保留文章深度、概念順序、推導、例子、來源與內部連結。篇幅縮短應來自消除重複，不以固定壓縮比例為目標。
- 遵守所在資料夾的編輯與引用規則。逐字稿、原始證據或其他受保護內容，依其編輯授權處理。
- 如果任務本身是進度報告、查核紀錄、交付驗收或研究限制說明，完成狀態與證據界線可能就是正文，應保留其用途。

## 判斷一個補充是否該留下

先問：**拿掉這句，讀者會不會因此誤解概念、證據、適用條件，或要採取的下一步？**

| 句子的作用 | 處理方式 |
| --- | --- |
| 只在交代下載、登入、整理、核對或工具執行經過，與本段教學無關 | 從正文移除；確有追溯用途時，集中到既有附錄或來源說明 |
| 反覆說明文章不等於完成課程、取得能力、採用建議或達成目標 | 調整標題、語氣或狀態欄位，讓身分清楚；刪掉逐段重複的聲明 |
| 在排除讀者根本沒有被引導去相信的主張 | 刪除，讓文字直接說明真正要教的事 |
| 揭露常見誤解，且能改變練習方式 | 保留區分，改成具體機制、例子或可操作的檢查 |
| 限制研究結果、數據或方法的適用範圍 | 就近用簡短文字保留；不要讓改寫後的主張變得更強 |
| 重要來源缺失，使某個結論尚無依據 | 保留不確定性、縮小主張或標示推論；不能只刪掉限制留下結論 |
| 不同來源對同一命題確有衝突 | 保留雙方說法、引用與條件，不以潤飾名義選邊 |

「不代表」「不保證」「未確認」「不能據此」都是檢查線索，不是禁用詞。同樣一句話放在學習解說與交付報告中，處理方式可能不同。

## 修訂方式

### 1. 先讀懂全文

讀完指定檔案與適用規則，確認讀者、主題與用途。記下主要段落、例子、推導、連結、引用與結構化欄位；編輯前留一份暫存副本供比較，避免覆蓋先前已存在的修改。

找出讓閱讀停頓的主要原因，例如：每段末尾都有免責聲明、混入工具紀錄、同一觀念反覆換句話說，或使用了難以想像實際動作的詞。先處理主要原因，不把所有句子一律重寫成同一種風格。

### 2. 清除重複交代，安排必要資訊

- 一個重要限制通常在主張附近交代一次即可。後文只有在可能重新造成誤解時才補充。
- 跨全篇的來源身分，可在開頭或既有來源區簡短說明；例如區分課程內容、研究補充與延伸練習。
- 將建議寫成「可以試試……」「練習建議」等自然語氣，不必每段再補「尚未採用」「未在讀者身上驗證」。若文章要記錄承諾或進度，仍須維持準確狀態。
- 與正文無關但值得追溯的版本或平台規則，可收進文末補充。在支援的 Markdown 環境中可使用收合區塊；不要為一次潤稿另建資料庫、追蹤頁或新流程。
- 不把必要限制全部藏到文末。例如研究只測了某種任務，就在介紹結果時交代任務範圍。

### 3. 把生硬句法改成能理解的動作

- 把抽象名詞串接改成主詞、動作與對象。例如「進行知識提取與錯誤校準」可寫成「先合上教材回答，再核對並修正錯誤」。依上下文保留需要學習的正式術語，第一次出現時用白話解釋。
- 一段先說明一個概念，再接理由或例子。不要解釋到一半插入來源整理歷史。
- 將沒有必要的「不是 A，也不是 B」改成直接說明做法；真正有助理解的對照可以保留。
- 少用含糊的代詞與抽象動詞。說清楚誰做什麼、在哪個條件下有用、怎樣檢查。
- 拆開同時承載定義、例子、限制與操作建議的長句，讓前一句自然帶到下一句。

### 4. 保留學習價值與原意

刪掉重複聲明後，確認原本的概念區分、原因與例子仍在。錯誤或有爭議的內容不能因文字變順就當作已確認；只對影響本次改寫的問題回查來源，不自動擴成全面研究。

保留原有引用，讓它跟著所支持的主張移動。新寫的應用以「例子」「延伸練習」「建議」等方式標明。不要新增無來源的事實，也不要把「可能」改成「一定」、把相關改成因果、把個人故事改成普遍效果。

## 改寫示例

以下均為自製示例，用來說明判斷方式。

**把重複的能力聲明改成練習方向：**

> 原：認得名詞不表示能解決問題，也不能保證換個情境仍會判斷。
>
> 改：認得名詞後，再練習用自己的話解釋，並比較它在兩種情境中是否適用。

若本段正在教「辨認」與「應用」的差別，也可直接保留對照，接上一個具體例子。

**讓建議身分一次說清楚：**

> 原：這個安排由整理者提出，不表示讀者已經採用，也尚未證實對每個人有效。
>
> 改：練習建議：先選一個小主題，試做後再依結果調整。

**簡化限制，但保留結論範圍：**

> 原：這項結果來自特定的短文任務，不能保證所有專業技能都會有同樣效果。
>
> 改：這項研究測的是短文回憶；應用到其他技能時，仍要用對應任務檢查表現。

若文章下一步正要用短文研究推論專業技能，這個限制就應留在該主張附近。

**整理紀錄依文章用途處理：**

> 原：目前只整理了操作頁面，尚未逐項執行，所以這份文字不能當成測試通過紀錄。
>
> 處理：方法解說中可移除這句；測試報告中則保留實際執行狀態，集中到結果段。

## 完成前檢查

- 讀回真實檔案的全文，特別留意開頭、轉折與結尾；不能只檢查被刪掉的字串。
- 對照暫存副本，確認概念順序、必要例子、推導與實質限制仍在。調整標題時，檢查指向該標題的連結。
- 檢查 Markdown 表格、引用、內部連結、數學符號與結構化欄位。使用當前環境適用的檢查方式，不要求安裝額外工具來完成單次潤稿。
- 搜尋原本反覆出現的聲明，逐處確認留下或移除的理由；不要為了讓搜尋結果歸零而刪掉必要文字。
- 按所在地規則更新日期或整理紀錄。回覆以檔案連結與主要修改為主，避免再用一串免責聲明重現原本的問題。
