# 課程與舊版時間軸格式契約

僅供維護既有的舊版時間軸筆記。新的影音與課程筆記一律依 note-format.md（reading-v3），不要再用這份格式產生新筆記。寫筆記前讀完；`MN check` 會檢查其中可機械驗證的部分。

## Frontmatter

```yaml
---
title: "<筆記標題>"
date: 2026-09-15                     # 建立筆記的日期
source_type: youtube                 # youtube | podcast | course
source: "https://www.youtube.com/watch?v=..."   # 課程填錄音檔路徑，多個用「 + 」連接
channel: "<頻道／節目／授課者>"         # metadata 沒有就省略，不要猜
published: 2026-09-14                # 只有 probe 給得出來才寫
duration_seconds: 4180               # transcript JSON 的 duration，check 用它驗證時間軸終點
transcript_method: "youtube-subs:zh-TW"   # 或 "asr:mlx-community/whisper-large-v3-turbo"
slides:                              # 只有課程路線
  - "1.Introduction-to-AI.pdf"
research: "perishable-facts-checked" # 或 "none"
tags:
  - type/video-note                 # 依 source_type：youtube → type/video-note、podcast → type/podcast-note、course → type/course-note
  - source/youtube                   # source/podcast、source/course
---
```

`type/*-note` 標籤要和 `source_type` 對得上（`check` 會擋）。來源沒有可用時間戳時，加 `timeline_mode: degraded`，時間軸段落改用 `### 講述順序 N：標題`，`check` 就不驗時間範圍；筆記開頭要用 callout 說明為什麼降級。

## 章節順序

必要章節依序出現（`check` 會擋）：

1. `## 一分鐘摘要`
2. `## 核心心智模型`
3. `## 容易混淆的概念`
4. `## 完整時間軸筆記`
5. `## 主動回憶問題`

選配章節放在合理位置：`## 素材與可信度`（表格包進可摺疊 callout）、`## 外部查證來源`。

**超過 8 個時間軸段落時要分組**：`## 完整時間軸筆記` 底下用 `### <主題分組>`，段落降為 `#### [時間] 標題`。8 段以內不分組，段落維持 `### [時間] 標題`。分組是為了讓 Obsidian 右側大綱有中層可跳，4–6 組、每組 2–6 段。

## 時間軸段落

```markdown
#### [12:10–15:42] 相關性分手：利差不再解釋日圓

[▶ 12:10](https://www.youtube.com/watch?v=ID&t=730s)

- **核心主張**：講者在這段要證明什麼。
- **必要細節**：
	- 支撐主張的機制、例子或數字（只留會改變理解的）。

> [!abstract]- 白話解釋
> 第一次出現的難概念，一個術語一行。

![[系統/附件/<筆記名>/frame-03_13m05s.jpg]]
*圖：2025/6 之後藍線（利差）與紅線（匯率）分開走——這就是「相關性分手」的證據。*

> [!research]- 外部查證
> 外部資料確認、補充或限制了什麼。
> [來源 A](https://...) · [來源 B](https://...)
```

規則：

- 時間範圍連續、不重疊、從 00:00 開始、到結束（容許 5 秒內誤差）。業配或閒聊也要有段落，可以一行帶過：「業配：<品牌>，略」。
- 時間格式：一小時以內 `MM:SS`，超過用 `H:MM:SS`，與逐字稿一致。多段錄音用逐字稿的累計時間。
- YouTube 每段放「▶ 跳到該秒」連結（`&t=<秒數>s`）；Podcast、課程不放。
- 每段最多一個研究 callout；圖片最多 1–2 張。
- 同一概念只在第一次出現時完整解釋，之後只補新的例子或限制，並連回第一次的段落。
- **子項一律用 Tab 縮排，一層一個 Tab，不要用空格。** 空格縮排在 Obsidian 會畫在錯的深度、也不畫縮排導引線（`check` 會擋）。唯一例外是 YAML frontmatter，那裡規格禁止 Tab，用 2 個空格。

## 可摺疊與強調

Obsidian callout 語法是 `> [!type]` 加標題，`[!type]-` 預設摺疊。**讀的時候要看的東西不摺疊，查的時候才看的東西一律摺疊。**

| 用途 | 寫法 | 摺疊 |
| --- | --- | --- |
| 來源與素材說明 | `> [!info] 來源` | 否 |
| 術語白話解釋 | `> [!abstract]- 白話解釋` | 是 |
| 逐字稿校正表、無內容區段 | `> [!warning]- <說明>` | 是 |
| 外部查證 | `> [!research]- 外部查證` | 是 |
| 主動回憶題（答案收在裡面） | `> [!question]- <題目>` | 是 |

規則：

- 白話解釋一律用 `> [!abstract]- 白話解釋` 放在該段條列之後，不要當成條列的一項。多個術語就一個術語一行 `> - **術語** —— 解釋`，不要擠成一句話。
- callout 裡的表格每一行都要 `> ` 開頭。
- `==高亮==` **全篇只用 2–3 處**，留給真正要背起來的定義。用多了就失效，粗體已經足夠標示次級重點。
- 不要用 HTML 標籤。callout、`==高亮==`、mermaid 已覆蓋需求，HTML 匯出到其他工具會壞掉。

## 圖片

- 只放承載資訊的畫面：圖表、流程圖、關鍵字卡、文件截圖、投影片。主持人鏡頭、情境 B-roll 不放。
- 每張圖下一行斜體說明：「這張圖顯示什麼、為什麼跟這段有關」。沒說明的圖不要放。
- 課程投影片標註來源頁：`*投影片 D2 p.12「Representation」：…*`。p.N 指 PDF 第 N 頁，不是投影片上印的頁碼（兩者常差 1）。
- 圖檔一律用 `MN export-frames`／`MN export-pages` 產生到 `paths` 給的附件資料夾，嵌入語法直接用指令輸出的 `embed`。

## 用語

- 繁體中文、台灣用語。正文用台灣慣用譯名（日圓、川普、軟體）；直接引用逐字稿時保留原文用字。
- 術語第一次出現：先白話說明它做什麼、為什麼在這裡重要，再附英文或縮寫，例如「大型語言模型（LLM）—— 靠預測下一個字來生成文字的模型」。解釋裡不能再出現沒解釋過的術語。
- 一句話最多引入兩個新術語。例外（不用解釋）：API、URL、CPU、HTTP、JSON、SQL、Git、CLI、AI、PDF。
- `check` 會列出「第一次出現卻沒有說明記號」的縮寫，逐一確認。

## 逐字稿可信度

- `transcript_method` 是 `asr:` 時，專有名詞要用 probe 的 metadata（頻道、節目、作者、描述、PDF 術語）校正；metadata 裡沒有的名字寫「（音譯，未確認）」，不要猜。
- 逐字稿中標 ⚠ 的句子不當成原話引用，只寫「講者大意」。
- 轉錄有大段缺漏（`quality.low_text_windows`）或語言判斷異常時，在 `## 素材與可信度` 用表格寫出區間與影響。

## 密度

- 技術課程／講座：每分鐘約 6–10 行（含 callout）。
- 閒聊型 Podcast、直播：每分鐘約 3–6 行，重點放在論點、數字、判斷依據。
- 每一點都要帶來新的主張、例子、區別、機制或影響；外部補充的篇幅要少於逐字稿內容。

## 主動回憶問題

3–5 題，**每題都要附答案**，用 `> [!question]- <題目>` 把答案收在摺疊區裡，章節開頭寫一行「先自己想過再展開答案」。沒有答案的題目等於無法自測，不算完成。

涵蓋：

- 用高中生聽得懂的話解釋核心機制。
- 套用到一個具體情境。
- 指出一個會失效或被誤用的條件。
- 把整集壓縮成一條操作規則。
